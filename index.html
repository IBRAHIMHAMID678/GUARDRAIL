GUIDES

The problem with simple rules

Teams block AI agents with simple text rules like git commit. They think: "the agent can't commit."

But the rule only stops that exact text. The same commit can be written many different ways — and most of them slip right past a simple text rule.

Why not use an AI to judge?

Some tools use an AI to grade security. That's slow, gives different answers each time, and can be tricked.

This lab uses plain, fixed logic instead. The same input always gives the same answer — on any computer, every time.

A perfect score is not a proof

Scoring 100% here means your rule caught these 14 attack cases. It doesn't mean it's secure against everything.

Real safety needs checks at several levels — this tool shows you where your text rule stops working.

Level 1 Text check Reads the command text before it runs. Fooled by extra flags, full paths, and extra spacing. Fix: split the command into parts (command name + action) and check those.
Level 2 Shell tricks The shell understands chains (&&, ;) and $(...) before anything runs. Rules expecting the command at the start fail. Fix: check each part of a chained command separately, or block chaining.
Level 3 Git hooks conceptual — not executed by this tool Git's own safety checks live inside the repo. The --no-verify flag turns them off completely. Fix: enforce rules on the server (GitHub / GitLab), not just on the computer.
Level 4 Repo settings conceptual — not executed by this tool Branch protection and required reviews on GitHub / GitLab. Agents can't switch these off. Fix: turn on branch protection and required approvals.
  • Only 20 tests: the shell can spell the same command in endless ways — these cover the most common tricks, plus innocent lookalikes.
  • No live watching: this is a simulation. It doesn't track what actually runs on your computer.
  • Doesn't read your git settings: it can't know the personal command nicknames you've set up.
  • Made for one job: checking the text rules and command filters that developers write for their agents. It assumes an agent that emits command variants — sloppy, clever, or prompt-injected — not a nation-state attacker. It tests the filter, not the agent's intent.
WHAT I NOTICED

Teams building AI coding tools usually block bad actions with lists of exact words — git commit, rm -rf, curl | bash. Writing the rule feels like enforcing it. It isn't.

WHAT I TESTED

The idea that a text pattern stops an action. The same action has dozens of valid spellings — git -C /repo commit walks right past a naive rule.

WHAT I KEPT SMALL

Instead of a giant shell parser or an unpredictable AI judge, I built a small fixed test set: 14 tricky commands plus 6 innocent lookalikes (so overblocking gets caught too), clear check levels, before/after score tracking, and 16 self-checks for the engine itself.

THE TAKEAWAY

Test your defenses — don't just assume they work. And layer them: smart checks where the agent runs, plus server rules that can't be switched off.
