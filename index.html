TECHNICAL BRIEFING

The Guardrail Paradox: Syntax vs Intent

Developers configure tool execution restrictions on coding agents using naive string filters: git commit, curl | bash, rm -rf.

They believe: "The agent cannot commit code."
The mathematical reality: "The agent cannot emit this specific 10-byte UTF-8 string."

Because shell execution environments possess rich parsing semantics (aliases, subshells, path prefixes, interleaved flags, process substitution), a literal string matcher fails against 60%+ of realistic command transformations.

Why Deterministic & Zero LLMs?

Many AI evaluation products introduce LLM judges to "grade" security. This is an anti-pattern. LLM judges are non-deterministic, slow, vulnerable to token order, and introduce hallucinated security boundaries.

Guardrail Lab's core evaluator is 100% deterministic client-side JavaScript. Identical inputs yield bit-for-bit identical verdicts across browsers and operating systems.

Corpus Coverage Is Not A Security Proof

Scoring 100% on this 14-case corpus means the guardrail successfully intercepted these 14 specific vectors. It does NOT prove security against arbitrary unbounded POSIX shell expansions. Real defense requires tokenized argument validation at the execution boundary and branch protection at the repository platform.

LAYER A Command Pattern Matcher Filters string text before passing to child process. Bypassed via whitespace, flags (-C), and path prefixes (/usr/bin/git). Fix: Parse executable basename and tokenized arguments.
LAYER B Shell Interpretation POSIX shell expands $(which git), compound chains (&&, ;), and escapes (\git). Matchers anchored with ^ fail. Fix: Restrict shell chaining or inspect each pipeline stage independently.
LAYER C Git Hook Layer Client pre-commit hooks. Completely bypassed via --no-verify or -n. Irrelevant to command filters. Fix: Enforce server-side branch protections and CI status checks.
LAYER D Repository Workflow Branch protection, signed commits, and mandatory PR approvals on GitHub/GitLab. The only immune layer. Fix: Platform-level RBAC and branch lockdown.
  • Finite Corpus: Curated 14 vectors represent high-frequency transformations, but shell grammar allows infinite combinatorial encoding (e.g. eval $(base64 -d ...)).
  • No Live Process Tracing: Static simulation does not observe eBPF syscalls or dynamic binary renames on disk.
  • No Host Environment State: Does not query local .gitconfig for active aliases; models the syntactic form of an alias invocation.
  • Harness Focus: Built specifically to evaluate developer-defined command regexes and token filters.
WHAT I NOTICED

Teams building AI coding agent platforms routinely rely on blocklists of literal strings (git commit, rm -rf, curl | bash). They confuse having written a string rule with having enforced an operational policy.

WHAT ASSUMPTION I ATTACKED

The assumption that a pattern matcher intercepts an operation. In shell command syntax, the exact same semantic intent takes dozens of equivalent forms. An agent that outputs git -C /repo commit easily bypasses naive filters.

WHAT I DELIBERATELY KEPT SMALL

Instead of an unmaintainable full POSIX grammar parser or an unpredictable LLM judge, I built a deterministic 14-vector adversarial harness with explicit layer categorization, instant Before/After delta tracking, and 13 unit tests for the tester itself.

THE TAKEAWAY

Defenses must be tested, not assumed. And defense-in-depth requires structured token enforcement at the agent boundary combined with immutable server-side policies at the repository boundary.
